# Project knowledge

This directory is the durable project memory for `ai-setup`. GitHub Issues and pull requests track work; this directory records only context that remains useful beyond a task. `docs/` describes verified behavior, while approved future decisions remain clearly labeled as intent.

There are no knowledge notes yet. The approved project-knowledge design is recorded in [Issue #76](https://github.com/ehuerta6/ai-setup/issues/76), and its implementation was delivered in [Issue #79](https://github.com/ehuerta6/ai-setup/issues/79) and [PR #80](https://github.com/ehuerta6/ai-setup/pull/80). Use the [project-knowledge skill](../skills/project-knowledge/SKILL.md) for the current workflow. Those GitHub records remain canonical and are linked here rather than copied into notes.

When durable context is relevant, search this directory for the current topic and read only matching notes. Use the `project-knowledge` skill to capture explicitly approved decisions, maintain evidence-backed context, reconcile contradictions, or run a Knowledge Review when requested. A routine issue or pull request does not require a note.

Add `decisions/`, `architecture/`, or `context/` only when useful notes exist. Use descriptive Markdown filenames and relative links. Keep product documentation in `docs/` and active task history in GitHub.
